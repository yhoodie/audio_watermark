### 项目简介   
这是一个音频数字水印嵌入和提取工具，可嵌入文字、图像、音频三种类型的水印，可嵌入水印大小会在上传载体后提示。

## 本地开发

### 环境要求

```
# Node.js ≥ 20
# npm ≥ 10
例如：
# node -v   # v20.18.3
# npm -v    # 10.8.2
```

具体安装步骤如下：

### 在 Windows 上安装 Node.js

```
# Step 1: 访问Node.js官网：https://nodejs.org/，点击下载后，会根据你的系统自动选择合适的版本（32位或64位）。
# Step 2: 运行安装程序：下载完成后，双击运行安装程序。
# Step 3: 完成安装：按照安装向导完成安装过程。
# Step 4: 验证安装：在命令提示符（cmd）或IDE终端（terminal）中输入 node -v 和 npm -v 来检查 Node.js 和 npm 是否正确安装。
```

### 在 macOS 上安装 Node.js

```
# Step 1: 使用Homebrew安装（推荐方法）：打开终端。输入命令brew install node并回车。如果尚未安装Homebrew，需要先安装Homebrew，
可以通过在终端中运行如下命令来安装：
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
或者使用官网安装程序：访问Node.js官网。下载macOS的.pkg安装包。打开下载的.pkg文件，按照提示完成安装。
# Step 2: 验证安装：在命令提示符（cmd）或IDE终端（terminal）中输入 node -v 和 npm -v 来检查 Node.js 和 npm 是否正确安装。
```

### 安装完后按照如下步骤操作：

```
# Step 1: 下载代码包
# Step 2: 解压代码包
# Step 3: 用IDE打开代码包，进入代码目录
# Step 4: IDE终端输入命令行，安装依赖：npm i
# Step 5: IDE终端输入命令行，启动开发服务器：npm run dev -- --host 127.0.0.1
```

## 项目背景   
### 为什么做这个   
&emsp;&emsp;因为面试的时候被问Vibe Coding经验。虽然面试不是模拟考，没有范围与边界，下次问的内容很可能毫不相关，但我实在是下意识复盘……既然提到了那就做一下呗。   
&emsp;&emsp;至于为什么之前没做呢，一方面是工作项目庞大，需要理解模块关联与逻辑，加载和编译都要长耗时的项目似乎不太方便纯Vibe，会使用AI但是还是得自己主导代码；一方面是自己没有需求，之前对Vibe Coding挺好奇的，但是没有什么具体要开发的内容和想法，硬去复刻一个已有的东西似乎也没什么意思，就一直搁置。至于仓库里前两个AI编程的代码，一个是刮刮乐有具体内容限制，不是通用类工具，不方便聊需求，自己调方便些；一个是纯逻辑代码，而非工程性代码，感觉重点在核心逻辑上而且无法进行测试，还得自己看源码检查。   
### 为什么是这个   
&emsp;&emsp;简单介绍一下我的毕业设计：独立完成从选题、需求分析到工程及算法设计全套流程，完成了《基于数字水印的版权保护与图像溯源技术研究与开发》，包含身份系统、水印系统、攻击系统和评价系统，数据库包含用户表和发布表，以及登录、注册、用户信息、上传、设置、发布、压缩、攻击、提取、评价十个界面（不含报错提示框等）。   
&emsp;&emsp;学校没有这个方向的老师，我的论文也是草稿即终稿，其实单挑一部分出来就完全够毕业了，中期答辩的时候答辩组老师说工作量非常饱满。如此困难重重的情况下，当时还是靠着自力更生古法编程做完了……明明老师们出的题都挺简单（基本都是课设水平，所有路径都规定死了，工作量也小），却非要给自己出难题，对此我朋友的评价是：![同学评价](./image.png)   
所以，我对这个项目还是非常印象深刻的！而且能自力更生做完也算是自己感兴趣的内容吧！其实也不算全做完，因为列举的这些甚至只是我最初规划的一部分……我把本来要做没做的部分写成未来展望留给下一届了，但下一届也没返回结果，估计是没写出来，嗐。那个本来要做的未来展望都又裂变成好几个题了，当时真是初生牛犊不怕虎啊哈哈哈，啥都想做，做不完根本做不完。   
&emsp;&emsp;于是最终选择了展望的一部分来尝试。当然，现在心里是很有数了，身份系统、攻击系统和评价系统都省略了，也不考虑什么多格式载体了，多格式水印都是考虑了一下才放进去的。什么水印分存、阈值设定等等更复杂的内容更是不在考虑范围内。试水嘛，差不多得了，搞那么复杂费时费事还容易做不出来。需要再慢慢迭代，先做核心功能。   
&emsp;&emsp;选这个的好处是非常明确的。我感兴趣，且我熟悉。虽然我做的是图像载体，这里的需求是音频，算法不一样，但系统设计和大致思路还是心里有数的。虽然时间久了记忆模糊，但代码细节又不需要我写，算法也不需要我来设计，这些模糊的印象足够了。   
## 复盘总结   
### 总结   
&emsp;&emsp;这还有什么可总结的？
### 感想   
&emsp;&emsp;以上就是我看到结果的唯一想法。被震撼到的我脑子里只有这一句话。原本我是打算看看多agent专家团的方式分工的，各司其职，就像人类产品、UI设计、程序员、测试这样分工。但是想起去年想尝试的秒哒，就想试试使用体验，然后再跟更专业的模式做对比。我的预期是需求分析上总有需要确认的东西吧，总要多轮对话然后找bug吧，总有些瑕疵吧，总有些坑要踩吧，我复盘就是要复盘这个呀！结果呢？我就输入了79个字：
>帮我做一个客户端。界面1：可上传载体和水印，输出嵌入水印后的载体。载体目前限定上传音频文件，水印可选文字、图像、音频。界面2：上传音频文件，输出提取对应水印。   

然后就根据这简单的描述，秒哒就自动生成了一份详细的需求文档，再等一个多小时，一切就都完成了。我做了什么？我只简单描述了自己的需求，然后什么都没有做。这我还总结什么？？？硬要总结的话，需求描述要清晰？但是其实我完全没有考虑边界问题、选用什么算法、界面如何设计等等，我只是简要描述了核心功能。而且它的界面设计比我更好，问题考虑得比我更周到，许多我要多次迭代的问题，它一次就完成了。包括水印容量提醒这种小细节都有考虑到，这种得是我焦头烂额真手搓过才会注意到的细节，就像只有自己手搓过才知道右键菜单复制粘贴这种完全习以为常的东西都是要程序员一点点写出来的，不是全部集成好默认就会带这些功能。但是AI不一样，习以为常的东西会成为AI的本能，潜移默化到不需要考虑，就默默存在。甚至AI还会自动分析哪些要哪些不要，不要的会归到“本期不实现功能”中，也是非常有价值的值得后续迭代实现的内容，其中一些也确实是我考虑以后暂时舍弃的功能。   
&emsp;&emsp;甚至它有logo，有界面设计，最后展现给用户的，是可用的程序界面与界面设计结合，前面的按钮都是可以正常使用的，而背景甚至还有设计网格，甚至多次交互后还有版本控制和修改简述，下载代码以后还带git文件夹和gitignore文件，以及README。本文档的第一部分就是自动生成的，我删去了一部分不必要的内容，改了一点小瑕疵。除了本文档后半部分和引用的图片，这个仓库其他文件我完全没有修改，一点代码都没有看。
&emsp;&emsp;当然，非要说的话还是有些问题的。但完成度确实相当震撼。比如prd中应用描述就是“一款桌面客户端工具”，但实际上是用前端写的。可能是我的要求是客户端吧，需求稿倒也没毛病，但后续实现没按照这个来。第一版自动实现了提取出来的音频带播放功能，但载体音频和嵌入音频没有。当然这个也能理解，上传的载体和水印都没必要听，输出的加水印后载体通常也是下载使用没必要听，这个设计是合理的，只不过我要直接对比是否可感知，所以让加上了播放功能。   
&emsp;&emsp;而且我觉得这个计费不是很合理，按照对话轮数进行扣费，生成prd文件是一轮，开发是一轮，改bug会修改prd文件+改代码合起来算一轮。但一个多小时的开发和十几秒的修改是一个价格……嗯，倒逼一次性说清楚全部需求哈哈哈哈哈也挺好。说来说去所有的问题我都能找到解释。   
&emsp;&emsp;不禁在想，AI越来越聪明，那还要我们做什么呢？也许是越来越“内容为王”？当技术壁垒不断被消解，最后比拼的是谁的想法更好。工具越来越易用，对于不同领域来说，都是时间流逝时代发展的必然，技术不该是思想的阻碍，而应是表达的助力。   
&emsp;&emsp;同时也在想，如果我当年毕设也能这么写，也许我能完成原本的超大规划，并且过程会愉快得多，不用为报错和bug而痛苦，可以把精力完全放在系统设计上。但同时我也会忽略底层实现细节，比如嵌入的是时域、频域还是空间域？使用哪种算法嵌入？不知底层又如何改进呢？一味让AI把健壮性提得再高一些？不可感知性做得再好一些？但是这些特性与评价手段都是需要对原理有所了解。也许该考虑的是对知识的了解边界吧。就好像现在又有多少人在写汇编呢。   
&emsp;&emsp;看到效果以后果断买了会员，后面我会给更复杂的需求，看看完成度如何。大模型回答问题还在前言不搭后语，同一段内容自相矛盾不觉得有问题，这个开发水平对比起来简直太震撼了。其实AI中的很多概念，比如agent、skill，也像代码最初学习时对象、函数这些概念一样，是为了减少重复劳动。有迹可循的规则在被不断以更高维度的总结方式折叠。   


PS：内容又真是人类专属的闪亮特质吗？AI评论越来越精彩了。而且AI在很早以前没有火热的时候就因AI对话创造语言可能产生意识令人类胆寒了。如今的发展……
